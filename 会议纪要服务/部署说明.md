# 部署说明（腾讯云 Ubuntu · Docker · 8081 自签）

> 目标机器：`ubuntu@VM-0-5-ubuntu`（已运行两个项目，**本服务不碰它们**）
> 已占用端口（实测 `ss -ltnp`）：
> - `8080` → nginx（www-data，PID 304839–304842）
> - `10802` → python（ecmwf 项目，PID 2314506）
> **本服务只用 `8081`**，经 Docker 网络内部转发，不改动 nginx、不改动现有 python 服务。

---

## 0. 部署前必须先修仓库（否则镜像构建会失败）

实测仓库 `splider-debug/meeting_minutes`（main 分支）里**只有 `会议纪要服务/` 一个目录**，
缺少镜像构建必需的 `tools/` 与根目录文件：

| 缺什么 | 后果 |
|---|---|
| `tools/`（9 个脚本） | `docker build` 执行到 `COPY tools/ ./app/tools/` 直接失败 |
| `会议资料整理SOP.md`、根 `.gitignore` / `.gitattributes` / `.dockerignore` | 版本控制不完整，不影响运行但应补 |

另外 **`会议纪要服务/示例/` 里有真实姓名，而仓库是 Public**：

- `示例/A_261120/03_初三期中家长会及中考备考安排.docx` 及其 md —— 含**本班学生真实姓名**与成绩
- `示例/261119`、`示例/B_261118` —— 含客户单位、报价等商务信息

**处理顺序（建议）**：

```powershell
# ① 立刻把仓库改成 Private：Settings → General → Danger Zone → Change visibility
#    （学生姓名已在公开历史里存在过，改私有是最快的止损）

cd C:\Users\ju\Desktop\会议资料整理

# ② 示例不进库（它是演示产物，部署不需要）
Add-Content .gitignore "会议纪要服务/示例/"

git rm -r --cached 会议纪要服务/示例

# ③ 补上 tools/ 与根文件
git add tools 会议资料整理SOP.md .gitignore .gitattributes .dockerignore

# ④ 只有一个提交，直接修正（用 --amend 让示例从历史里消失）
git commit --amend -m "init: 会议资料整理 SOP + tools 工具链 + 会议纪要服务（M1-M4）"
git push -f origin main
```

> `git push -f` 之后旧提交在 GitHub 上会变成不可达，一般不主动删除；
> 若对"学生姓名曾公开"这件事敏感，改 Private 即可，不必纠结历史。

## 1. 服务器环境体检（只读，先跑这一步）

```bash
# 系统与资源
lsb_release -ds; uname -m
nproc; free -h | head -2; df -h / | tail -1

# Docker 是否已装
docker --version 2>/dev/null || echo "docker 未安装"
docker compose version 2>/dev/null || echo "compose 未安装"

# 8081 是否空闲（应为空）
sudo ss -ltnp | grep ':8081' || echo "8081 空闲 ✅"

# 公网 IP（Caddyfile 要填这个）
curl -4 -s ifconfig.me; echo
```

**判断标准**：

| 项 | 要求 | 不满足怎么办 |
|---|---|---|
| 内存 | ≥ 4 GB（paddle OCR 峰值约 1.2 GB） | 2 GB 机器先加 2 GB swap，见 §8 |
| 磁盘 `/` 可用 | ≥ 12 GB（镜像 1.5 GB + 构建缓存 3 GB + 数据） | 清理或扩盘 |
| 8081 | 空闲 | 换端口（改 `docker-compose.yml` 的 `ports` 与 `Caddyfile` 两处） |

## 2. 安装 Docker（未安装时）

```bash
sudo apt update
sudo apt install -y ca-certificates curl gnupg

sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg \
  | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list >/dev/null

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo usermod -aG docker $USER && newgrp docker
docker run --rm hello-world          # 验证
```

> Docker 会新增 iptables 链与 `docker0` 网桥，但只会监听你在 compose 里声明的 `8081`，
> 不会抢占 8080 / 10802，也不影响 nginx。

## 5. 构建与启动


首次构建如果卡在 pip，检查是否需要国内源；可临时在 `Dockerfile` 的 pip 命令加：

```dockerfile

```

## 6. 放行 8081

```bash
# 系统防火墙（若开启了 ufw）
sudo ufw status
sudo ufw allow 8081/tcp
sudo ufw reload
```

**腾讯云控制台**：安全组 → 入站规则 → 新增 `TCP:8081`。
来源建议先填**你自己的出口 IP**（查 `curl -4 -s ifconfig.me`），验证通过后再考虑放开。

## 8. 与现有两个项目共存（重点）

| 现有服务 | 端口 | 本服务的处理 |
|---|---|---|
| nginx（www-data） | 8080 | 不改它的配置、不占用 80/443；Caddy 自带 HTTPS 只监听 8081 |
| ecmwf python 项目 | 10802 | 完全独立，容器内网段 `172.x`，不与其冲突 |

- **不要**为了部署去 `apt install nginx` 或改现有 nginx 的 server 块——本服务自带 Caddy 反代。
- 如果以后想挂到现有 nginx 后面（复用 443），可以停掉 caddy 容器，改 `docker-compose.yml` 为
  `app` 只 `expose` 8000 并加 `ports: ["127.0.0.1:18081:8000"]`，再由 nginx `proxy_pass http://127.0.0.1:18081;`
  并关掉 `proxy_buffering`（否则 SSE 进度会被缓冲）。当前方案不需要这么做。

**内存不足时加 swap**（2 GB 机器构建镜像容易 OOM）：

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h
```

## 9. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `COPY tools/ ... not found` | 仓库没推 `tools/`（见 §0） | 补推后重新 build |
| 构建被 OOM killed | 内存 < 4 GB | 加 swap（§8），或改用轻量镜像（§10） |
| `8081 address already in use` | 端口被占 | `sudo ss -ltnp \| grep 8081` 查占用者，换端口 |
| 页面打开是旧内容 | 浏览器缓存 | Ctrl+F5 |
| 上传后进度不动 | 反代缓冲 SSE | Caddyfile 必须有 `flush_interval -1` |
| 浏览器证书警告每次都出现 | `tls internal` 12 小时轮换 | 正常；想免警告就换域名 + Let's Encrypt |
| 图片任务报 `OCR 初始化失败` | 见 `README.md` §八 | Python 3.11 镜像里是 paddle 2.6，通常正常 |
| 磁盘涨得快 | 成品未清理 | `ARTIFACT_TTL_SEC=3600`，清理器每分钟扫；查 `du -sh /opt/meeting_minutes/会议纪要服务/data` |


**要备份的只有 `.env`**（`data/` 里是模型缓存和 1 小时内就过期的产物，可重建）：

```bash
cp /opt/meeting_minutes/会议纪要服务/.env ~/meeting.env.bak
```

### 可选：把镜像从 1.5 GB 降到约 400 MB

现在镜像装的是 `paddleocr 2.9 + paddle 2.6`（Python 3.11 上工作正常）。如果你本地验证过
RapidOCR 可用（`python check_env.py --ocr-init --ocr-run` 显示 `引擎就绪 RapidOCR`），
可以把服务端也切成 RapidOCR，构建会快很多：

1. `requirements-server.txt` 改成 `-r requirements-core.txt` + `-r requirements-ocr-rapid.txt`
2. `Dockerfile` 删掉 OCR 预热那一行 `RUN python -c "from paddleocr import PaddleOCR..."`
3. `docker compose build --no-cache`

要不要切，看你本地那条命令的结果再定。
