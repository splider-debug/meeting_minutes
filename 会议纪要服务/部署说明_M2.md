# M2 部署说明（腾讯云 Ubuntu + 8081 自签）

> 目标：把 M1 的流水线装进容器，通过 `https://<公网IP>:8081` 上传文件并下载成品。
> 当前是 **M2 冒烟版**：单任务、同步返回、无进度流（SSE 在 M4）。

## 一、本地先验（不需要 Docker）

```powershell
cd C:\Users\ju\Desktop\会议资料整理\会议纪要服务
.\venv\Scripts\Activate.ps1

# 起服务（口令自定义）
$env:AUTH_PASSWORDS='huiyi2026'
$env:SESSION_SECRET='本地随便一串'
uvicorn app.web:app --host 127.0.0.1 --port 8099
```

浏览器开 `http://127.0.0.1:8099` → 输口令 → 传 docx → 下载。

命令行验证也可以：

```powershell
# 健康检查
Invoke-RestMethod http://127.0.0.1:8099/healthz
Invoke-RestMethod http://127.0.0.1:8099/readyz

# 带登录态上传
$null = Invoke-WebRequest http://127.0.0.1:8099/auth/login -Method Post -Body @{password='huiyi2026'} -SessionVariable s
Invoke-RestMethod http://127.0.0.1:8099/api/render -Method Post -Form @{file=Get-Item '路径\某纪要.docx'} -WebSession $s
```

## 二、服务器部署

```bash
# 1) 装 Docker
sudo apt update && sudo apt install -y docker.io docker-compose-plugin git
sudo usermod -aG docker $USER && newgrp docker

# 2) 拉代码（整个仓库，因为镜像要用根目录的 tools/）
git clone <你的仓库> /opt/meeting && cd /opt/meeting/会议纪要服务

# 3) 配置
cp .env.example .env
vim .env      # 必改：AUTH_PASSWORDS、SESSION_SECRET（openssl rand -hex 32）、DEEPSEEK_API_KEY
vim Caddyfile # 必改：把 203.0.113.10 换成你的公网 IP

# 4) 放行端口（腾讯云控制台安全组里也要加 8081 入站）
sudo ufw allow 8081/tcp && sudo ufw reload || true

# 5) 构建并启动（首次约 5—10 分钟：paddle 依赖 + 模型预热）
docker compose build
docker compose up -d

# 6) 验证
curl -kfsS https://<公网IP>:8081/healthz
docker compose logs -f app | head -50
```

浏览器 `https://<公网IP>:8081` → 出现证书警告点"高级 → 继续前往" → 输口令。

## 三、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `docker compose build` 报 `COPY tools/ not found` | 构建上下文不是仓库根 | 必须在 `会议纪要服务/` 目录执行，compose 里已写 `context: ..` |
| 容器起来就退出 | `.env` 里 `AUTH_PASSWORDS` 为空 | `readyz` 会返回 503，检查 `.env` |
| 首次请求很慢/超时 | 模型没预热成功（构建时离线） | 进容器跑一次 `python -c "from paddleocr import PaddleOCR; PaddleOCR()"`，或让构建机联网 |
| 上传大文件 413 | `MAX_UPLOAD_MB` 或 Caddy `max_size` | 两边一起调 |
| 证书警告每次都出现 | `tls internal` 证书 12 小时轮换 | 正常；想免警告就换域名 + Let's Encrypt |
| 磁盘涨 | 成品没清 | `ARTIFACT_TTL_SEC=3600`，服务在下载/新建任务时惰性清理 |
